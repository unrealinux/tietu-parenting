# 数据源方案（v1，待确认）

四个层，各自有固定入口和落地位置。新增数据只往「入口」丢，转换和规范化由脚本做，不直接改模板。

## 1. 素材层 —— 真实图片

| 项 | 内容 |
|---|---|
| 入口 | `materials/<slug>/01.jpg`、`02.jpg`…（3:4 最佳） |
| 声明 | post JSON 里加 `"photos": ["01.jpg", "02.jpg", "03.jpg"]` |
| 生成 | `tietu_queue.py --slug <slug> --style photo --commit` |
| 输出 | `output/tietu/<slug>/photo/` |
| 状态 | ✅ 已上线，实测通过 |

规则：第 N 张卡用第 N 张图，图不够重复最后一张。优先级高于 AI 图。

## 2. 选题层 —— 从哪来写什么

| 项 | 内容 |
|---|---|
| 入口 | `references/intake/`（截图、评论原话、一句话小事、关键词，任意格式） |
| 沉淀 | `topics.md` 选题池：选题 / 来源 / 情绪点 / 状态（待写、已写、已发） |
| 生成 | 我从池子取，写成 `posts/*.json` |
| 状态 | ⏳ 目录已建，池子待建 |

规则：先有来源再写，不凭空白想。一条爆款截图能拆出标题结构、首图信息密度、结尾问句。

## 3. 数据层 —— 表现的反馈

| 项 | 内容 |
|---|---|
| 单篇阅读 | `output/stats/articles.json`，来源：截图读图 或 `log_stats.py` |
| 粉丝增减 | `output/stats/user_summary.json`，来源：`fetch_stats.py`（API） |
| 不可得 | 微信已下线单篇数据 API（47009），后台也不再支持导出，只能截图/手记 |
| 状态 | ✅ 工具就绪，数据待导 |

规则：只看「发布后 48 小时」的口径，累计阅读会被时间干扰。

## 4. 风格层 —— 长什么样、什么口气

| 项 | 内容 |
|---|---|
| 规则 | `references/SOP-流程.md`、`references/manual-notes.md` |
| 基线 | 已有 67 篇贴图 + 26 篇 story 的文案，作为口吻样本 |
| 状态 | ✅ 已有 |

规则：新写的内容必须和基线同款——第一人称妈妈、具体时间点、结尾一个能回答的问句。

## 生成层（数据怎么变成草稿）

```
posts/tietu_*.json      --style photo | comic  --> output/tietu/<slug>/  --> 草稿
posts/story_*.json                              --> output/story/<slug>/ --> 草稿
```

每天 08:30 / 15:30 各建 1 批（1 贴图 + 1 story），库存低于 2 批时任务显示失败提醒补货。
