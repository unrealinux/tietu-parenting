# 微信贴图号生产流程

规则来源：生财有术「微信贴图号」Mini 航海实战手册。完整要点见 `references/manual-notes.md`（赛道表、搜索词、复盘表、红线）。

代码位置：`E:/Project/feiyingqi-wechat-ainews`（脚本已就绪，见文末命令）。

## 六条硬规则

违反任何一条，内容基本白做。

1. **1–3 张图**。首图负责让人一眼看懂主题。
2. **组图必须递进**：后一张要补充新场景 / 新细节 / 新证据 / 新对比 / 新选择。
   自检：遮住其中一张，如果整条内容完全不受影响 → 这张只是装饰，删掉。
3. **正文不重复图上的文字**，结尾放一个用户能立刻回答的问题。
4. **只用两个发布入口**：公众号助手 App、微信公众平台官网。
   **不要用微信内置「公众号」入口直接发贴图**——不进标准发布链路，影响流量主收益。
5. **选题能写成一句话**：具体人群 + 高频场景 + 可重复素材 + 明确互动。
6. **红线**：不制造广告点击、不刷虚假数据；不搬原图/原文/人物经历；不用恐吓、擦边、夸大标题。

## 步骤

### 1. 选题 + 拆对标（只拆 3 点）
- **话题**：这组图可以讲什么事？
- **图片吸引力**：首图靠什么让人停下来？（数量 / 反差 / 陌生物件 / 动作 / 结果）
- **情绪切口**：好奇、怀旧、心疼、治愈、选择、共鸣？

每个候选方向留 3–5 条近期仍有互动的内容，保留 2–3 个候选方向后再定主方向。
**只记录链接、时间、人群、主情绪、首图结构、评论区讨论点。不要保存原图做发布素材。**

二创边界：可以学题材、构图、标题层级、组图顺序、互动机制；不能搬原图原文。
完成标准：**关掉参考内容后，成品仍能独立成立。**

### 2. 写内容
- 标题：让用户一眼看懂方向，可用「你们那边叫什么」这类结构，但不要照抄原句
- 短文案：补图片没说的事实和细节，不重复图上文字
- 结尾问题：用户能立刻回答的选择题或经历题，不要空泛的「你怎么看」

### 3. 出图
优先级：**自己拍摄 / 明确授权 / 正规图库（pexels、pixabay）** ＞ AI 生成底图 ＞ 只有必须配一句话才成立时才叠加标题文字。

- 交给脚本的 cards 保持 **1–3 张**（第一条尤其如此），并在 JSON 里自查递进
- 首图主体清楚，不糊不乱，不需要解释半天
- 1–3 张图都在讲同一件事，不要旅行、美食、职场混在一起
- 参考截图不等于发布素材。带水印、账号名、平台标识的图不发布

### 4. 发布前只检查 4 项
1. 图片、标题、正文是同一个主题，首图一眼能看懂
2. 图片清楚、顺序正确、没有重复图或错字
3. 正文不重复图上文字，结尾问题自然好回答
4. 图片、文字、事实来源已核对，没有直接搬运

### 5. 建草稿（走 API，不群发）
```bash
cd E:/Project/feiyingqi-wechat-ainews
PY="C:/Users/Administrator/AppData/Local/Programs/Python/Python314/python.exe"
"$PY" scripts/publish_tietu.py posts/<post>.json --images-only   # 先只看图
"$PY" scripts/publish_tietu.py posts/<post>.json                 # 出图 + 建草稿
```
- post JSON 结构：`{slug, title, content, cards:[{text, sub}]}`；对比卡用 `{a, b}` 代替 `text`
- 走 `article_type=newspic`（贴图/图片消息），只建草稿，不群发
- **不要用 Windows 自带的 `python`**（微软商店 stub，静默退出 49），用上面的完整路径
- 报错码：`40164` IP 不在白名单 / `41001` token 失效 / `45003` 标题或正文超长 / `48001` 该账号无此接口权限
- 永久素材接口有频控，连传会被断链；脚本已做间隔与退避，不要改成并发上传

### 6. 复盘
每轮按「曝光 → 打开 → 互动」找问题，一次只改一个变量：

| 现象 | 优先检查 | 下一轮动作 |
|---|---|---|
| 几乎没人点开 | 选题是否具体、标题和首图是否清楚 | 保留素材，只换标题或首图 |
| 有人读但很少互动 | 情绪是否明确、问题是否好回答 | 保留主题，重写互动问题和正文场景 |
| 评论多但方向发散 | 用户实际在讨论什么 | 从评论提取下一条选题 |
| 某类素材连续有反馈 | 共同人群、场景、标题结构 | 做系列延展，不急着换赛道 |
| 连续测试无信号 | 素材条件、赛道宽度、表达方式 | 先调整一个层级再决定换不换细分 |

- **同方向连续发 3–5 条再复盘**，不要用一条数据决定整个账号方向
- **突然掉流量先排查**选题跑偏 / 标题首图不一致 / 素材版权风险；不要一着急就删文重发
- 记录 9 项：赛道与细分、素材来源、选题与标题结构、阅读与推荐变化、评论数量与内容、转发与收藏、人工修改记录、下一条动作
- 三句话复盘卡：今天最好的反馈 / 当前最明显的问题 / 下一条只改哪个变量

## 账号前期六个不要
1. 不要今天职场、明天旅游、后天养生
2. 不要频繁修改昵称、头像、简介
3. 不要同一套图文在多个账号同步复制
4. 不要数据不理想就频繁删文重发
5. 不要恐吓、擦边、夸大或事实不清的标题
6. 不要一开始就同时运营多个账号——先把单号流程跑通

## 平台观察的 5 个维度
账号垂直度 / 内容原创度 / 停留与阅读 / 互动 / 更新稳定性。

**流量入口**：公众号或服务号消息入口、搜一搜、看一看、内容详情页底部、相关推荐。
里面没有「粉丝推送」——贴图号主要靠推荐流分发，新内容低阅读有正常成分。
